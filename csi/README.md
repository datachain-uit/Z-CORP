# CSI evidence workspace

This folder is the venue-specific evidence workspace for the CSI submission. It registers
campaigns and records where every piece of evidence comes from. It does **not** hold a second
copy of any source campaign: `results/postcorr-20260925/` stays the only source of truth for
CSI-PROVER-01, and nothing here is edited by hand except the registry and the notes listed below.

Other venues fork this layout (a new `<venue>/` folder with its own registry) and reference the
same source campaigns by path, campaign ID and sha256.

## Layout

| Path | What it is | How it is made |
|---|---|---|
| `campaign-index.csv` | Registry: one row per campaign used for this venue (administrative fields and identities). | Hand-maintained; every identity is checked by the build script. |
| `protocols/prover/RERUN-PROTOCOL-v3.md` | Byte-identical snapshot of the protocol at the campaign commit. | Generated from `git show <commit>:submission/csi/RERUN-PROTOCOL.md`. |
| `campaigns/prover/CSI-PROVER-01/SOURCE.sha256` | sha256 of all 51 files of the source campaign (`shasum -a 256 -c` from the repository root). | Generated once, then frozen: a later mismatch aborts the build. |
| `campaigns/prover/CSI-PROVER-01/campaign.json` | Registration, campaign/commit/tag/protocol/image identities, validation, superseded-campaign digest, image-archive record, derived-output checksums. | Generated. |
| `campaigns/prover/CSI-PROVER-01/derived/` | Manuscript-facing derivations (`prover_*.csv`, `values.tex`, `derivation.json`). | Generated by `scripts/analysis/derive_prover.py` (accepted attempts only). |
| `campaigns/prover/CSI-PROVER-01/notes/report-vs-derivation.md` | Completion-report numbers vs the scripted derivations. | Generated by `scripts/analysis/compare_completion_report.py`. |
| `campaigns/prover/CSI-PROVER-01/HOST-ACTIVITY-NOTE.md` | Disclosure of host activity during the campaign. | Hand-written. |
| `investigations/` | Post-campaign investigations (input stage, PLONK scaling). Engineering diagnostics here are **not** campaign data. | Hand-written notes; diagnostic output from `scripts/analysis/input_stage_diagnostic.js`. |
| `code/prover/KIT.sha256` | The code the campaign ran: every file of the campaign paths at the campaign commit. | Generated from git. |
| `code/analysis/ANALYSIS.sha256` | The derivation and release scripts used to build this workspace. | Generated. |
| `provenance/SNAPSHOTS.csv` | Origin (source, campaign ID, commit, tag, protocol, image manifest/config) and sha256 of every file in `csi/`. | Generated. |
| `release/` | Release archives and their checksums. Binaries are not versioned (`release/.gitignore`); `RELEASE.sha256` and `IMAGE-ARCHIVE.json` are. | `scripts/release/build_csi_bundle.py --release`; the image archive by `scripts/release/save_image.sh` on the campaign host. |

## Rebuild and check

From the repository root:

```
python3 scripts/release/build_csi_bundle.py            # rebuild generated files (deterministic)
python3 scripts/release/build_csi_bundle.py --check    # exit 1 if anything is stale
python3 scripts/release/build_csi_bundle.py --release  # also rebuild the release archives
shasum -a 256 -c csi/campaigns/prover/CSI-PROVER-01/SOURCE.sha256   # source campaign unchanged
bash scripts/release/save_image.sh                     # campaign host only: docker save of the image
```

### Chain campaigns (`campaigns/chain/`)

Chain campaigns are registered in the same `campaign-index.csv`. Their layout differs from the prover campaign, because they have no pre-existing source campaign directory.

| Path | What it is | How it is made |
|---|---|---|
| `protocols/chain/CHAIN-PROTOCOL-v1.md` | The protocol. The L1 arm is frozen; the local-EraVM arm is pending. Pre-run amendments are logged in its §15. | Hand-written, committed (not a snapshot) |
| `campaigns/chain/CSI-CHAIN-LOCAL-01/inputs/proofset/` | The frozen proof set PS-01: 64 proofs and their manifest | `chainbench/scripts/gen_proofset.js`, once, never regenerated |
| `campaigns/chain/CSI-CHAIN-LOCAL-01/inputs/plonk-verifiers.provenance.json` | Provenance checks for `contracts/chain/PlonkVerifierDepth*.sol` | `chainbench/scripts/export_plonk_verifiers.js` |
| `campaigns/chain/CSI-CHAIN-LOCAL-01/campaign.json` | Registration, identities (protocol, harness commit, container image, lockfile, compiler, EDR and geth binaries, proof set) and the validation state | `chainbench/workloads/zcorp/record_campaign.py` (reads the campaign binding) |
| `campaigns/chain/CSI-CHAIN-LOCAL-01/notes/` | The dry-run records and the proof-set generation record | `DRY-RUN.md` (packaged dry run) is generated; `DRY-RUN-readiness-<commit>.md` keeps the earlier readiness dry run; `PROOFSET-GENERATION.md` is hand-written |
| `chainbench/workloads/zcorp/campaigns/CSI-CHAIN-LOCAL-01.json` | The campaign binding: the only place where the venue-neutral chainbench core learns the CSI campaign id, protocol, frozen inputs, tracked/measurement paths and baseline-tag prefix | Hand-written, committed |
| `chainbench/README.md` | Reviewer instructions: `./chainbench/run.sh doctor`, `smoke`, `full-local-l1` (Docker only) | Hand-written |
| `code/chain/CSI-CHAIN-LOCAL-01.KIT.sha256` | The chain campaign's code at its registered commit | `scripts/release/build_csi_bundle.py` |
| `release/CSI-CHAIN-LOCAL-01/` | `docker save` archives of the scientific image (linux/arm64), of the official geth image it was built from, and of the linux/amd64 portability image. The archives are not versioned; their records (`IMAGE-ARCHIVE.<arch>.json`, OCI index, listing) and `IMAGE-ARCHIVE.json` are. | `./chainbench/run.sh save-image` on the campaign host; `scripts/release/chain_image_record.py` |
| `campaigns/chain/CSI-CHAIN-LOCAL-01/notes/PORTABILITY.md` | Archived images and the reviewer-platform check (linux/amd64 doctor and smoke) | Hand-written from the records |

- **Raw run data** goes to `build/campaigns/chain/<run_id>/` (git-ignored).
- **After the scientific run** (not started), the raw data is archived into `release/CSI-CHAIN-LOCAL-01/` and the derived outputs go to `campaigns/chain/CSI-CHAIN-LOCAL-01/derived/`.

The pre-correction July 2026 files are superseded; their provenance is `results/PRECORRECTION-2026-07.sha256`,
whose digest each campaign record carries as `superseded_campaign`.
